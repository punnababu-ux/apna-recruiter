# Poneglyph audit — October 2026

Scope: the design-system package, the ApnaHire / marketing / docs surfaces,
build tooling and docs. Method: six parallel code audits (build+docs, token
and composition rules, two primitive sweeps, responsiveness, product logic),
an adversarial verification pass, a live crawl of all 34 routes (server
status, hydration, console), and a horizontal-overflow sweep at 320 / 375 /
768px. 89 findings came in. 30 were machine-verified, and the
higher-severity ones were re-checked by hand before fixing.

---

## 1. Fixed in this pass

### Build and tooling
- **`next build` failed type-checking** because the tsconfig `**/*.ts` glob
  pulled in `packages/design-system/tsup.config.ts`. It is now excluded.
  `npm run check` passes end to end.
- **Semantic motion tokens generated no classes.** They were wired as
  `--animate-duration-*` while Tailwind's `duration-*` reads
  `--transition-duration-*`, so `duration-hover`, `duration-enter` and the
  rest were dead. They are now rewired, and the new motion tokens use the
  same path.
- `card-hover-lift` used raw `220ms` / `cubic-bezier` values. It now uses tokens.

### Contrast and accessibility
- **Warning text was unreadable.** Alert `warning`: about 2.2:1 in dark mode.
  Badge `warning` (gold on gold tint): about 2:1. Dark-mode `*-subtle-fg`
  tokens had no dark value, so they were about 1:1. Every status role now
  has a dark `-subtle-fg`, they are exposed as
  `text-<role>-subtle-foreground`, and Alert, Badge and the banner accent
  use them. Measured: 8.2:1 light, 7.3:1 dark.
- AlertBanner `appearance="primary"` + `warning` put white text on the light
  gold gradient. It now uses the dark warning foreground.
- AlertBanner's inline action removed the focus outline with no
  replacement. It now has a focus ring.
- **Checkbox and Radio never looked disabled.** Base UI renders a `<span>`, so
  `disabled:` never matched. Both now use `data-disabled:`.
- Slider thumb had no keyboard focus ring (the focusable element is the
  inner `<input>`). Fixed with `has-focus-visible:`.
- Tabs dropped `orientation` (only a data attribute was set), so vertical
  tabs kept horizontal keyboard semantics. It is now passed to Base UI.
- Tabs `inverted` lost its dark chip in dark mode. Fixed by the new
  indicator.
- BottomNav marked the active tab by colour alone. It now also shows a pill
  behind the icon and a semibold label.
- Stepper didn't expose the current step. It now sets
  `aria-current="step"`.
- "Create new job" was an unlabelled icon below 640px. It now has an
  `aria-label`.
- The marketing header's hidden sub-nav was `aria-hidden` but still
  focusable. It is now `inert`.
- Payment-method tags used classes that generated no CSS
  (`text-*-subtle-fg`). They now use the exposed tokens.
- The docs Select demo showed the raw value (`mid`) in the trigger. It now
  passes `items` for labels.

### Responsiveness
- **The product shell overflowed at tablet width.** `SidebarInset` lacked
  `min-w-0`; `/apnahire/jobs` was 61px wider than a 768px screen.
- **The job detail page overflowed at 320 and 375px.** The tab strip now
  scrolls, the view toggle is `shrink-0`, and the CandidateCard action bar
  wraps.
- **The marketing site had no navigation below 1024px** (`mobileOpen` was
  never set). It now has a menu button and a right-hand sheet with every
  nav group.
- **Self-checkout:** database credits were unreachable at 640–767px
  because the hero switched layout at `md` and the body at `sm`. Both now
  switch at `md`.
- Dialogs could grow past the viewport on phones. They are now capped at
  `100dvh − 2rem` and scroll inside.
- Inputs used 14px text, which makes iOS Safari zoom on focus. They now use
  `text-base md:text-sm`.
- Bottom-fixed bars ignored the home indicator. The app now sets
  `viewport-fit=cover`; BottomNav and the checkout CTA dock use the new
  `pb-safe` / `pb-safe-<n>` utilities.

### Docs
- AGENTS.md pointed at `src/components/ui` and `src/styles/tokens`, which no
  longer exist. The paths, file map and lint scope are corrected.
- AGENTS.md required T-shirt spacing utilities (`p-md`, `gap-md`) that are
  deliberately not generated. They are removed from the "Required" table.
- TOKENS.md now documents the status `-subtle-fg` pairing rule and the
  motion tokens. COMPONENTS.md lists `InkProvider`.

## 2. New: live surfaces (micro-interactions)

A small interaction language, built into the primitives so every screen
gets it for free. Full rules are in AGENTS.md, and there's a live demo on
**Foundations → Radius & Motion**.

| Utility | What the user feels |
|---|---|
| `ink` | While pressed, an ink spreads from the touch point; on release it fills the surface and fades into the hover state |
| `press` / `press-subtle` | The control gives under the finger (0.97, or 0.99 for cards) |
| `transition-interactive` | Colour, border, shadow and focus ring ease instead of snapping. Replaces `transition-all` |
| `transition-select` | Ticks, radio dots, switch thumbs and chevrons land with a slight spring |
| `tab-indicator` | One indicator glides between tabs |

Applied to: Button, Toggle / ToggleGroup, ChipTabs, SegmentedTabSwitcher,
Tabs, Checkbox, Radio, Switch, Slider, Accordion, dropdown and select items,
Select trigger, Input, Textarea, PromptInput, SidebarMenuButton, BottomNav,
AlertBanner, clickable PricingCard, the checkout bundle rows, the pricing
chips, the marketing nav and the docs index cards.

How it works:
- The ink uses no per-component JavaScript. It is CSS on `::before`, and
  one document listener (`<InkProvider/>`) supplies the press point.
- Only colour, opacity, clip-path and transforms animate.
- Hover stays hover-only (`@media (hover:hover)`).
- Reduced motion keeps a held tint and drops the movement.
